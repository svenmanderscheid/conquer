# Union of Kingdoms app start

The shared sign-in and game pages include `views/partials/app-start.php` before their interface. The start screen reuses the approved village WebP variants and game logo; its responsive styles live in the final shared `village-theme.css`.

On 6 October 2026, the screen gains a localized daily-quest tip and separate artwork/progress-restoration status. `kingdom-entry.css` is included before `village-theme.css` on the sign-in and game pages. Startup no longer holds at 100% for an extra delay: only the 300 ms visual fade remains, with immediate dismissal for reduced motion. Failed startup exposes the existing reload action; a later successful state refresh hides it and completes normally. Scripts loaded after document completion also finish correctly.

The existing background illustration has a slow 12-second CSS zoom using only `transform`; it adds no image or startup wait and is clipped only within the decorative image layer. Both the operating system's reduced-motion preference and the game's `body.reduced-motion` class disable it completely.

`assets/js/app-start.js` starts at 0%, advances with document and non-lazy image loading, and reaches 100% only after the page load and, in the game, the first successful state refresh and rendering. Percentages represent startup milestones, not transferred bytes. The completed screen fades away. A failed initial state request or a 30-second wait offers an explicit reload; background polling can still complete startup. Reduced motion and safe screen edges are respected. English, German, French and Luxembourgish text uses the shared language catalogs.

After removing the overlay, startup dispatches `conquer:startup-complete`. The beginner adviser waits for that event before opening a native dialog, so a top-layer dialog cannot cover unfinished loading. Existing browser/player welcome state remains the only automatic-intro marker. The event itself grants no progress or reward.

Local verification on 4 October 2026: sign-in start screen, card bounds and successful dismissal at 1280×800, 390×844 and 568×320; no JavaScript page errors. Captures: `artifacts/app-start/`. PHP/JavaScript syntax and all four JSON catalogs passed. Authenticated startup and a real Android device remain to be checked. The Android prototype loads the remote game URL and receives this shared screen after server deployment; its native launch screen is unchanged.

It holds an authenticated state request to check the actual loading overlay and progress below 100%, then verifies successful dismissal. There were no page errors or gameplay writes; Android device verification remains open.
