# Device notifications

Union of Kingdoms supports explicit device opt-in for browser Web Push and the Capacitor Android app (FCM HTTP v1). Enabling one device does not enable another. Permissions are requested only after the player presses Enable in the game menu. Missing server configuration is reported as unavailable; it is never simulated as successful delivery.

## Events and privacy

The defaults include separate completion texts for training, construction, research, healing and actual farm homecoming. Successful city attack and scout dispatch create immediate `battle_incoming` and `scout_incoming` events for the target. Successful city rally creation notifies the defender (`rally_incoming`) and the leader's other alliance members (`alliance_rally_player`); monster rally creation notifies those alliance members (`alliance_rally_monster`). Successful private chat creates `private_message` for its recipient only, inside the original replay-protected transaction. Rejected, rolled-back and replayed actions do not produce additional events. The scout arrival report remains in-game; push uses the start event instead of sending a duplicate arrival notice. Wall destruction remains supported. Device completion notifications are independent of the in-game completion-report preferences.

On the operator's explicit follow-up request, event texts include the relevant player display names and monster name, captured from authoritative server data at event time. Texts are localized in English, German and French, with complete shared catalog entries also in Luxembourgish; player and monster names are not translated. These names can appear on the lock screen. Private message contents, rally comments, coordinates, resource/battle details and internal account/world/event IDs are never forwarded. Only the localized game title/body, bounded display names, opaque random deduplication tag and fixed `city#city` route leave the server. Browser payloads are encrypted by the maintained Web Push library. Android uses Google FCM with the same event content. Device tokens are stored server-side only for opted-in sessions and are never included in query-string status requests or diagnostic output.

Existing device preferences remain compatible: `completions` covers activities and farm returns; `security` covers enemy warnings and the new `alliance`/`messages` delivery categories. Existing community channel mutes also apply. Muted private/alliance events are not created for later backfill. The worker rechecks current alliance membership, private channel mode, sender blocking and explicit chat read cursors before provider delivery, so departed members, blocked senders and already-read messages are suppressed. New push-only records are excluded from the ordinary notification feed and mailbox to avoid duplicating chat or creating generic letters. No schema migration, credential change or new Android build is needed for this extension.

Subscriptions belong to a player **and** login session. Logout revokes them; changing accounts in the same browser revokes the previous subscription before login replacement. A new account needs its own explicit opt-in. Expired sessions stop delivery (currently after seven days), and re-login requires enabling again. Removing a subscription also deletes its queued messages. Native token rotation atomically replaces the same session's token, preserving the device slot, preferences and queued deliveries; a lost response can be retried safely. A message already accepted by a provider cannot be recalled; it may contain the requested player/monster display names.

## Installation

1. Install the locked PHP 8.2+ dependencies with `composer install --no-dev --no-interaction --no-scripts --no-plugins`. PHP needs cURL, OpenSSL and mbstring. Deploy `vendor/` as well when the hosting environment has no Composer. The lockfile is committed; `vendor/` is ignored.
2. Run `php tools/migrate-push.php --check` against the confirmed game installation, then `php tools/migrate-push.php --apply` after reviewing the selected database, migration hash and prerequisites. This dedicated installer applies **only** `0145_web_push.sql`; do not use the general runner when other migrations are pending. It adds the subscription and outbox tables without changing game data. Do not enable the frontend server setting before this migration.
3. For browser push, run `php bin/create-push-keys.php mailto:YOUR_OPERATOR_EMAIL` once. It exclusively creates Git-ignored `config/push.php`, writes no keys to stdout and refuses to overwrite an existing configuration. Keep these application-specific VAPID keys backed up privately; changing them requires users to subscribe again. Set `enabled` to `true` after completing setup. The operator contact must be a real maintained address. On Windows/XAMPP, set `OPENSSL_CONF` to its installed OpenSSL configuration **before starting PHP** (for example `C:/xampp/php/extras/ssl/openssl.cnf`); runtime environment changes after PHP starts may be too late for key generation.
4. Schedule the CLI command `php /absolute/game/path/cron/push_tick.php` every minute on the server. This is a server cron job, not a Codex automation. Existing march/world cron jobs remain necessary for their own game events. The worker reports aggregate counts only. Exit code 2 means migration or provider configuration is missing.
5. Test with a dedicated account: enable, send a test, close/background the game, finish one queued activity, open its generic notification, disable, then repeat after logout and account change. No production device sends are performed by the automated test suite.

Configuration may instead use `UOK_PUSH_ENABLED`, `UOK_PUSH_SUBJECT`, `UOK_PUSH_PUBLIC_KEY`, `UOK_PUSH_PRIVATE_KEY`, `UOK_PUSH_NATIVE_ENABLED`, `UOK_PUSH_FIREBASE_PROJECT_ID` and `UOK_PUSH_FIREBASE_CREDENTIALS_FILE` environment variables. Never put private keys or service-account JSON in tracked files, browser bundles or the Android package.

### Targeted schema installation

The installer uses the ordinary application Bootstrap and its configured database; it never substitutes a local database or copies credentials. Without `--apply` it only inspects the schema and runtime. Its JSON output includes the database name, exact SQL SHA-256, migration marker, table presence, column/index/foreign-key drift, missing completion-producer prerequisites, PHP/extensions and Composer runtime/lock status. It does not read or print private push configuration or keys. Exit code 0 means the verified installation is ready, 2 means it is pending or runtime requirements remain unmet, and 1 means invalid arguments or an installation failure.

`--apply` takes a database-specific advisory lock, refuses to run inside an existing transaction, and validates any existing push tables before executing the two fixed additive CREATE statements. It never runs other migration files. After validating every expected column, default, index and revocation foreign key, it records only `0145_web_push.sql` in a short transaction. MySQL DDL commits implicitly, so there is no promise of schema rollback: a compatible partial installation can be retried safely, while incompatible existing tables or missing prerequisites stop the run without automatic repair. A missing prerequisite is an operator decision about the existing release, not permission to apply unrelated migrations.

### Android Firebase setup

Create a Firebase project and register the actual Android application ID used by `mobile/`. Add that project's client `google-services.json` only to the native Android build as described in `mobile/README.md`; it is separate from the server credential. Enable the Firebase Cloud Messaging HTTP v1 API. Use a service account with the required FCM sending permission, placing its JSON file **outside the web/document root** with access restricted to the PHP worker user. Configure its absolute path and matching project ID in private `config/push.php`, then set `native_enabled` to `true`.

The native channel ID is `uok_game`. The backend never relies on a legacy FCM server key. OAuth access tokens are obtained with Google's maintained PHP auth library and kept only in worker memory; all requests use fixed Google HTTPS origins and disable redirects. Unknown or expired registration tokens are removed when FCM reports `UNREGISTERED`. A new native build with the push plugin and matching Firebase client configuration must be installed before native push works. No Firebase project, private credentials, deployment or physical-device delivery is implied by implementing this code.

### Browser requirements

Use HTTPS (localhost is allowed for development), a supported browser, a registered service worker and permission. iPhone/iPad Web Push requires a supported iOS/iPadOS version and the game installed on the Home Screen; a normal Safari tab is insufficient. Android browser/PWA and the installed Capacitor app use distinct transports and separate opt-in. The latter does not gain browser PushManager support simply by loading the HTTPS game page.

## Delivery and operations

`PushWorker` settles at most 100 opted-in cities with due queues per run through the existing authoritative city/research processors and player locks. It also processes at most 100 opted-in players with due farm marches through the existing locked `MarchTick`, with a ten-second loop budget, covering arrival, gathering completion and actual homecoming while the app is closed. It does not invent gameplay outcomes. World context is restored after each city or march settlement. It captures bounded pages from existing durable notifications, skipping the historical backlog before subscription and events older than one hour. The opt-in baseline stays immutable while scans overlap, so a smaller notification ID that commits after a larger ID is not lost. A unique subscription/event pair prevents duplicate queue entries. The global worker lock prevents overlapping scheduled sends. Each run sends at most 50 records with a 45-second dispatch budget and bounded HTTP timeouts.

Temporary failures retry after 1, 2 and 4 minutes, at most four attempts. Sent/failed records retain aggregate outcome for seven days, then are pruned; unsent records older than one hour are discarded. 404/410 Web Push subscriptions and unregistered FCM tokens are removed. Provider results are recorded under short subscription/delivery row locks, after the HTTP request; an in-flight token rotation leaves the new token and its pending delivery untouched even if the old token's request succeeded or expired. A provider timeout after acceptance can result in a retry; the stable opaque notification tag replaces duplicate visible notifications when supported. This is best-effort delivery, not an exactly-once promise.

The sender accepts only HTTPS endpoints of recognized browser push providers, not arbitrary player URLs. Redirects, credentials, alternate ports and unrecognized hosts are rejected. All subscription changes and device status checks use authenticated, CSRF-protected POST requests. `expected_player_id` prevents a permission-dialog/account-switch race from silently binding the new account. GET status exposes only provider readiness for the current account and never a device identifier.

## API

- `GET /api/push/status?platform=web|android`: capability only; `enabled:false` without a device.
- `POST /api/push/status`: `{platform, endpoint}` for web or `{platform:'android', token}`, plus `expected_player_id`.
- `POST /api/push/subscribe`: web `{subscription:{endpoint,keys:{p256dh,auth}},locale,preferences,expected_player_id}`; Android `{platform:'android',token,locale,preferences,expected_player_id}`. Automatic native rotation adds `previous_token`, which must belong to the exact same player and session; it does not consume another device slot.
- `POST /api/push/unsubscribe`, `/api/push/test`, `/api/push/preferences`: same device identity; the last also accepts boolean `preferences:{completions,security}`.

Responses use the existing `ok/data/error` envelope. Status includes `available`, `public_key` (web only), `enabled`, `platform`, `player_id`, and preferences. Test returns `queued:true`; provider delivery happens on the next worker tick and is not asserted by the API response. Repeated test requests are deduplicated for one minute.

References: [Web Push PHP library](https://github.com/web-push-libs/web-push-php), [FCM HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api), [Apple Web Push](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
